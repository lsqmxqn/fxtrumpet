# FxMini

**只有 FxSound 的声音，没有 FxSound 的 App。**

托盘常驻的 Windows 音频增强工具。复用 FxSound 开源的 DSP 引擎与虚拟声卡驱动，
换掉它那套常驻的图形界面：没有主窗口，没有账号，没有联网，空闲内存约 **16 MB**。

## 这是什么

FxSound 的效果很好，但它的官方 App 是一个常驻的图形程序：内存占用三位数（MB）、带账号与联网、要一直开着主界面。如果你只想"让系统的声音变好听一点"，这些都不需要。

FxMini 把 FxSound 的两样东西留下来——**DSP 引擎**和**虚拟声卡驱动**——其余的换成一个小托盘程序：

- 系统里所有应用的声音都过增强，不只是某一个播放器（靠接管系统默认输出设备实现）；
- 需要调音时点托盘弹出一个面板，关掉就释放；
- 平时是一个图标，占用可以忽略。

因为 DSP 用的是上游**同一份源码**，声音与 FxSound 是**逐位一致**的，`.fac` 预设生态可以直接用。

仓库：<https://github.com/lsqmxqn/fxmini>

> 想了解实现细节：架构与选型见 [`docs/设计方案.md`](docs/设计方案.md)，踩坑与验证数据见 [`docs/开发笔记.md`](docs/开发笔记.md)。

## 特性

| | |
|---|---|
| **全系统生效** | 接管系统默认输出设备，所有应用的声音都经过增强，而不是只处理某一个播放器 |
| **音质与 FxSound 一致** | 直接用上游 DSP 源码编译，不是近似实现；`.fac` 预设可直接使用 |
| **占用小** | 空闲内存约 **16 MB**，空闲 CPU 约 **1.25%**；目标是最低限度的常驻 |
| **无主窗口** | 平时只有托盘图标；调音面板按需弹出，关闭后立即释放 GL 上下文与字体图集 |
| **31 段均衡器 + 5 个音效槽** | Fidelity / Surround / Ambience / DynamicBoost / Bass。均衡器是**一条可拖拽的频率响应曲线**，不是 31 行滑块，另有实时频谱显示 |
| **17 个内置预设** | Rock、Jazz、Movie、Gaming 等；自定义 `.fac` 丢进用户目录即可出现在菜单里 |
| **面板内保存预设** | 调完音在面板底部直接存成 `.fac`，立刻出现在预设列表与托盘菜单里 |
| **中英双语界面** | 托盘菜单与调音面板都跟随系统语言（中文 / English），也可在托盘菜单的「语言」里随时切换 |
| **跟随系统浅色 / 深色** | 面板整套配色是带对比度约束的设计令牌，切换系统主题即时生效 |
| **不会把你留在静音状态** | 崩溃或被强杀后，下次启动自动把默认输出交还给真实声卡；卸载脚本也这么做 |
| **开机自启（默认开）** | 默认开启，而且不是便利功能——见下面的说明 |
| **免安装、单文件** | 静态 CRT，不依赖 VC++ 运行库；打包成便携 zip，解压即用 |

### 关于开机自启

FxMini 必须**接管系统默认输出设备**，增强才会在音频链路里：

```
默认输出 = 虚拟声卡 ──> FxMini 回环采集 ──> DSP 增强 ──> 物理声卡
```

虚拟声卡是个死胡同，没有人从它取数据就是彻底的静音。所以一旦 FxMini 持有默认输出，**登录时它没起来就等于这台机器没有声音**。自启因此默认开启，启动时会把「期望状态」与注册表对账：

- 没有启动项 → 写入；
- 启动项指向**另一个位置**的 exe（换过目录、或开发时跑 `target/`）→ 重写，否则开机启动的是一个不存在的路径，而且悄无声息；
- 你在**任务管理器 → 启动**里手动关掉了 → **原样保留，不抢**，托盘里的勾选状态也会如实反映。

## 工作原理

```
任意播放器 / 系统声音
        │
        ▼
 ┌──────────────────┐
 │  FxMini 虚拟声卡  │   ← 系统默认输出被指向这里
 └──────────────────┘
        │  WASAPI 回环采集
        ▼
 ┌──────────────────┐
 │   FxSound DSP    │   31 段 EQ + 5 个音效槽
 └──────────────────┘
        │
        ▼
   真实声卡 → 扬声器 / 耳机
```

FxMini 自己写的是中间那段胶水：虚拟声卡的安装卸载、WASAPI 回环链路、托盘、面板，以及最关键的——**默认设备的接管与归还**。DSP 与驱动来自上游。

## 系统要求

- **Windows 10 / 11，x64**
- 安装虚拟声卡驱动时需要**管理员权限**（驱动是 FxSound 的签名包，由 Windows 校验）
- 使用预编译包不需要任何运行时依赖
- **从源码构建**另外需要 MSVC 工具集 + Windows SDK + Rust；仓库里的脚本会自动定位它们，见[从源码构建](#从源码构建)

## 安装

预编译包是 `FxMini-<版本>-win64.zip`，解压后是一个 `FxMini\` 目录：

```
FxMini\
  fxmini.exe               主程序
  driver\                  虚拟声卡驱动（fxvad.inf / .sys / .ntamd64.cat）
  README.txt               说明
  LICENSE.txt              许可
  install.ps1              单用户安装：复制到 %LOCALAPPDATA%、建快捷方式、启动
  uninstall.ps1            反向操作，含归还默认输出
```

**首次使用**：

1. 解压到任意目录（例如 `%LOCALAPPDATA%\Programs\FxMini`），双击 `fxmini.exe`，托盘出现图标；
2. 右键托盘 → **安装虚拟声卡…**，在 UAC 弹窗里允许；
3. 右键托盘 → **输出走 FxMini**；
4. 播放一段音乐，右键托盘 → **调音面板…** 调整音效；或从 **预设** 子菜单里挑一个；
5. 调得满意了，在面板最下面的**保存为预设**里填个名字存下来。

想装到 `%LOCALAPPDATA%\Programs\FxMini` 并创建开始菜单快捷方式，用管理员 PowerShell 跑一次 `install.ps1` 即可（它**不**安装驱动，驱动始终在第 2 步由你确认）。

**卸载**：跑 `uninstall.ps1`，或手动删除目录。卸载脚本会先把默认输出交还给真实声卡——否则你会留下一台没有声音的机器。

## 使用

### 托盘菜单

菜单按"你会先问什么"分成四组，组间有分隔线：

| 分组 | 菜单项 | 说明 |
|---|---|---|
| 打开 | 调音面板… | 打开调音窗口（已打开时再次点击会聚焦到现有窗口）。**左键单击托盘图标**也走这里 |
| 状态 | 启用音效 | 总开关，关掉即旁通 DSP |
| | 输出切到 FxMini | 把系统默认输出指向虚拟声卡。已经生效时这一项**会显示成「输出已切到 FxMini」并带勾**，而不是简单置灰——"灰了"曾让人分不清"已经好了"和"用不了" |
| | 预设 ▸ | 切换 `.fac` 预设，当前生效的一项带勾。**重新扫描预设**也挪进了这个子菜单（它本来在驱动那几项中间，离它刷新的列表差了六行） |
| 设置 | 开机自启 | 见上文说明 |
| | 语言 ▸ | **中文** / English，点一下立即切换，选择会被记住 |
| 维护 | 安装虚拟声卡… / 卸载虚拟声卡 | 会触发 UAC；不适用的那一项自动置灰 |
| | 退出 | 归还默认输出后退出 |

**左键单击或双击托盘图标 = 打开调音面板**，右键才出菜单——这是 Windows 托盘程序的习惯，也让这个"没有主窗口"的程序有了一个单击可达的入口。

菜单文案是**单语言**的（不带中英并排），默认跟随系统语言；切换语言会**就地改写各项文字**（`muda` 有 `set_text`），不再重建整个托盘——重建会闪一下图标，而失败时丢的是这个进程唯一的界面。

### 语言

托盘菜单与调音面板都带 **中文 / English** 两套文案：

- 首次启动**跟随 Windows 显示语言**——中文系统显示中文，其余显示英文；
- 想改就在托盘的**语言**子菜单里点一下：中文项写作「中文」、英文项写作「English」，所以即使当前界面是你看不懂的语言，也能认出该点哪个；
- 一旦手动选过，就把选择写进 `config.json`（`"language": "zh"` / `"en"`），此后不再跟随系统；
- 想恢复"跟随系统"，把 `config.json` 里的 `language` 改成 `"auto"`（或删掉这一项）。

### 调音面板与保存预设

右键托盘 → **调音面板…**，或直接左键单击托盘图标。面板本身也是双语的。关掉即释放 GL 上下文与字体图集，不留常驻窗口。

![调音面板](docs/panel-preview.png)

面板长这样：

- **标题栏和最小化 / 最大化 / 关闭按钮也是面板自己画的**，所以它和下面的卡片是同一套设计令牌，而不是一条系统灰栏。窗口没有系统边框：四角由面板自己裁（Windows 10 没有 DWM 圆角 API），边缘补了一圈 1 pt 描边，八个方向的缩放热区在窗口内侧 5 点——比系统边框薄，所以抓边的手感会比别的窗口稍需适应。
- **跟随系统浅色 / 深色**。所有颜色来自一份设计令牌（`src/ui/theme.rs`），两套调色板都按对比度标准挑过（正文 ≥ 4.5:1，大字与次要文字 ≥ 3:1，有单元测试盯着）；
- **均衡器是一条可拖拽的频率响应曲线**，不是 31 行滑块。拖动控制点改增益，双击归零，选中后方向键微调（`Shift` 更细）；频段数（5 / 10 / 15 / 20 / 31）与总开关在同一行；
- **窗口按内容自适应高度**：打开时量一遍卡片实际排布，再要一个正好装下的高度（不超过屏幕工作区）。控制卡片排成**两列**，所以整块界面在一屏内看全，不用滚动；窗口拉窄到 560 点以下会自动退回单列；
- 底部是**保存为预设**：填个名字点「保存」，当前的音效、均衡与输出设置会写成一份 `.fac`，落在 `%APPDATA%\FxMini\presets\`，随即出现在上方面板的预设列表与托盘的**预设**子菜单里——不需要手动「重新扫描预设」。重名会直接覆盖，所以调出一个满意的音色后可以再点一次保存把同一个名字刷新。

两处不显眼但要知道的行为：

- 名称里不能含 Windows 文件名不允许的字符（`\ / : * ? " < > |`），也不能用 `CON`、`NUL`、`COM1` 这类保留名。面板会当场提示，**不会**写出一个系统打不开的文件；
- 保存是**异步**的：面板把请求交给音频线程去写盘，完成后在底部回显「已保存 / 已覆盖 / 保存失败」。真正失败的原因（例如目录不可写）在 `fxmini.log` 里。

底部还常驻一行运行时读数（延迟 · 欠载 · 丢弃）与输入 / 输出设备名。欠载计数是帧数，几分钟就是八位数，所以那一行**按语言习惯缩写**（中文走万 / 亿，英文走 K / M / B），精确值放在悬停提示里。

### 命令行

| 参数 | 用途 |
|---|---|
| `--panel` | 启动时直接打开调音面板 |
| `--restore-output` | 把默认输出交还给真实声卡后退出。**"突然没声音"时的救命命令** |
| `--install-driver` | 安装虚拟声卡驱动（须以管理员身份运行，由主程序通过 UAC 自行调用，一般不用手敲） |
| `--remove-driver` | 卸载虚拟声卡驱动（同上） |

### 数据与配置

全部在 `%APPDATA%\FxMini\` 下：

```
config.json     设置（是否启用、当前预设、开机自启、界面语言、崩溃恢复标记）
presets\        预设目录：内置预设解包到这里，面板存的新预设也写在这里
fxmini.log      运行日志，排查问题先看它
```

## 疑难排解

**突然没有声音了**
FxMini 退出时会把默认输出交还给真实声卡；如果是被强杀或崩溃，勾选状态可能停在虚拟声卡上。跑一次 `fxmini.exe --restore-output` 即可。正常退出后再次运行 FxMini 也会自动修复。

**播放器/系统里多了一个 FxMini 设备**
这是正常的——虚拟声卡就是以这个身份出现在系统里的。不需要手动改默认设备，托盘菜单的"输出走 FxMini"会处理。

**开机后没有声音**
先确认 FxMini 有没有启动（托盘有没有图标）。如果没有，检查**任务管理器 → 启动**里 FxMini 是否被禁用；被禁用时 FxMini 不会强行打开它，只会如实显示。

**自己编译的 exe 没有图标**
`build.rs` 在编译期调用 `rc.exe` 把图标与版本资源写进 exe。找不到 `rc.exe` 时构建仍然成功，只是产出一个没有图标的 exe（会给出警告）。安装 Windows SDK，或用 `FXMINI_RC` 环境变量指向 `rc.exe` 的绝对路径。

**系统里还有一个 FxSound 的虚拟设备**
如果之前装过官方 FxSound，可能同时存在两个虚拟声卡。建议先卸载官方的那个，避免选错设备。

**面板里保存预设总是失败**
先看面板底部回显的是什么：名称相关的提示是当场拦下的（非法字符或保留名），改个名字即可；如果提示「保存失败」，就是写盘那一步出的问题，去 `fxmini.log` 找那行 `could not write preset`。最常见的原因是 `%APPDATA%\FxMini\presets\` 被安全软件锁住或权限被改过——手动确认那个目录能写就行。

**界面语言不对 / 想换回来**
默认跟随 Windows 显示语言，也可以在托盘菜单的**语言**里手动选。手动选过之后就不再跟随系统了，要恢复的话把 `config.json` 里的 `language` 改成 `"auto"`。

## 从源码构建

```powershell
# 一条命令：初始化工具链 + 构建（推荐）
.\build.ps1
.\build.ps1 --release --bin fxmini

# 等价的 PowerShell 手工两步
. .\toolchain.ps1
cargo build --release --bin fxmini
```

```bash
# Git Bash / MSYS
source toolchain.sh
cargo build --release --bin fxmini
```

> **为什么需要 `toolchain.ps1`**：本机的 Visual Studio 装在非默认路径且未向安装器注册，`cargo` 找不到 `link.exe`、`cc` 找不到 `cl.exe`。脚本负责定位真正完整的工具集并把它的 bin 前置到 PATH。细节与另外几个构建陷阱见 [`docs/开发笔记.md`](docs/开发笔记.md) 第 2 节。

`vendor/` 下的 127 个上游单元（DSP 94 + 辅助层 33）**已经随仓库提交**，clone 下来直接就能编，不需要先准备 `fxsound-app`。只有打算跟上游同步时才需要重新 vendor：

```bash
git clone https://github.com/fxsound2/fxsound-app ../fxsound-app
```

```powershell
.\vendor.ps1 -Source ..\fxsound-app -Dest .   # 幂等：只覆盖不删除，含上游补丁
```

### 打包

```powershell
.\package.ps1              # 构建 + 组装 dist/FxMini + 压缩
.\package.ps1 -NoBuild     # 只重新打包
```

产出 `dist/FxMini-<版本>-win64.zip` 与 `dist/SHA256SUMS.txt`。脚本含两项**强制**自检，不通过就失败：

1. exe 必须带图标与版本资源；
2. exe 不得依赖 VC++ 运行库——这个依赖在构建日志里完全看不见，只会在别人机器上表现为"程序打不开"。

第 2 项需要 `dumpbin.exe`，所以单独跑 `-NoBuild` 前先 `. .\toolchain.ps1`（让脚本自己构建时会自动处理）。

zip 里的**内容**是可复现的（`fxmini.exe` 在多次构建间哈希一致），zip 本身不是——zip 会记录每个条目的时间戳。要对比就比 `SHA256SUMS.txt`，别比 zip。

驱动三件套在 [`driver/`](driver/README.md)（约 343 KB，FxSound 签名版原样分发）：`package.ps1` 需要它，而 CI 没有同级检出可退，所以随仓库提交。

### 用 GitHub Actions 构建

不想配 MSVC 与 Windows SDK 的话交给 CI。推送到 `main` 或提 PR 会跑 [`.github/workflows/ci.yml`](.github/workflows/ci.yml)：

```
cargo check --all-targets --locked
cargo test  --lib --locked
build.ps1 --locked --release --bin fxmini
tools/inspect_resources.py target/release/fxmini.exe   # 独立复核 PE 资源
package.ps1 -NoBuild                                   # 两项自检 + 出包
```

绿色构建会把 `FxMini-<版本>-win64.zip` 作为 artifact 上传，Actions 页面直接可下载——**不发版也能拿到可分发件**。

> 那个 `#[ignore]` 的面板测试在 CI 里**不跑**：它会真的开一个窗口，需要交互式桌面会话。

### 发版

```bash
# Cargo.toml 与 Cargo.lock 里的 version 必须已经是本次要发的版本（CI 用 --locked）
git tag vX.Y.Z
git push origin vX.Y.Z
```

[`.github/workflows/release.yml`](.github/workflows/release.yml) 会打包并创建 Release，附上 zip 与 `SHA256SUMS.txt`。标签与 `Cargo.toml` 版本不一致时工作流**直接失败**：产物的文件名来自版本号，而人们引用的是标签，两者不能漂移。

手动触发（Actions → Release → Run workflow）则只产出 artifact、不创建 Release，用来在不发版的前提下验证整条打包链路。

## 开发与测试

```bash
cargo check --all-targets      # 零告警是硬要求
cargo test --lib               # 单元测试（另有 1 个真实开窗的测试默认忽略）
cargo test --lib -- --ignored  # 跑那个会真的打开一个窗口的面板测试
```

那个会开窗的测试有两个诊断用的环境变量，默认都是 0：

| 变量 | 作用 |
|---|---|
| `FXMINI_PANEL_TEST_DWELL_MS` | 窗口开好后停住这么久，用来肉眼审版式、或配合 `PrintWindow` 截图（README 里那张预览图就是这么来的） |
| `FXMINI_PANEL_TEST_SETTLE_MS` | 首个窗口打开前先等一会，用来对比"开窗前的私有内存"与"关窗后的地板值"——即窗口拆干净了没有 |

`fit_to_content` 那段窗口高度计算是纯函数，所以它有单元测试；窗口本身不会在 CI 里开。

改了工作流 YAML 之后，推之前先本地过一遍结构检查，免得白等一轮 CI：

```bash
python tools/check_workflows.py .github/workflows
```

三个诊断二进制，按"从离线到真机"的顺序：

| 命令 | 作用 |
|---|---|
| `cargo run --release --bin dspcheck` | 纯离线跑一段 1 kHz 正弦，验证 DSP 能编译、能解析真实 `.fac`、且确实改变了信号。**不涉及驱动与 WASAPI，报 FAIL 后面全白搭** |
| `cargo run --release --bin audiochk -- --seconds 5` | 跑真实回环链路，报告丢帧、削波与峰值 |
| `cargo run --release --bin audioenv` | 打印音频环境诊断；`--route-test 5` 实测默认设备切换与归还，`--restore-output` 手工撤销一次接管 |

## 版本历史

### 0.1.6

- **均衡器频段数不再停在 5 / 10，恢复 15、20、31。** 这个下拉框原先只有两项，旁边留了一行注释解释为什么：号称引擎只认 5 和 10，再多就没有频率published，"频段编辑器一片空白，拖节点也没反应"。**那行注释是错的**——引擎对 15/20/31 都有完整的频率表（`GraphicEqSetNumBands` 里 5/10/15/20/31 各有一张显式表，31 段就是 20 Hz–20 kHz 的完整 ISO 栅格）。真正让人看到空白的是别的东西。
  - **频段频率只在载入预设时才被读回来。** 引擎内部换了频段数之后会重算所有中心频率，但把结果抄回 `SharedParams` 的只有 `apply_preset` 这一处；**音频线程上那个 applier 只管把频段数推给引擎，从来不往回读**。于是 `params.band_freq()` 一直是 0，而绘制曲线的函数只要发现任一段频率 ≤ 0 就**直接返回**（那里写着"给一个编出来的横轴还不如空着"）。空白就是这么来的——不是引擎没有栅格，是没人去取。
  - 修法是在 applier 里补上这段回读，和 `apply_preset` 做同一件事。改的是一行注释里被当成事实的推断，所以顺带把那行注释重写了。
  - **新增回归测试直接驱动真正的 applier**，不是照抄它的逻辑。第一版测试是把 `set_num_bands` 和回读**内联**写了一遍，结果**把修复删掉它照样通过**——它测的是自己那段代码，等于什么都没测。现在走 `ParamApplier::apply`，把修复删掉会红：`step 0, 5 bands: band 0 came back as 0 Hz`，正是用户看到的那片空白。
  - 测试一次覆盖上行、下行（31 → 20 这种）和重复选择，并且比对**我们存的值和引擎自己的值**，避免只测到自己那份副本。
- **顺带记录一条关于 vendored 引擎的硬约束**：`DFXP_GRAPHIC_EQ_NUM_BANDS` 是**进程级全局变量**，不是句柄里的字段——一个进程里同时存在两个 `Dsp` 会互相踩，症状是**卡死**而不是崩溃。应用本身只建一个引擎（音频线程上，活到进程结束），所以在生产代码里碰不到；但按测试的写法，每个 `#[test]` 各建一个 `Dsp` 看着完全正常，实测会让第三个卡住超过一分钟。现在这些测试共用一个引擎并用锁串行化，`ffi::Dsp` 的文档里也写明了这条约束。
- 新增 1 个引擎测试，删掉 2 个（三者合并成同一个引擎上的一次往返遍历）。测试总数 69 → **70**。

### 0.1.5

- **修掉托盘「语言」菜单的对勾。** 报告的现象是两句话，但它们是同一个缺陷的两半：切到英文后，中文前面的对勾不消失（英文、中文同时带勾）；再次点击英文，反而把英文自己的对勾去掉了。
  - **对勾从来没有人移动过。** 语言项用的是**母语自称**（`中文` / `English`）——这是刻意的，让你切到一个看不懂的语言之后还能找回来——所以它们是整个菜单里**唯一不需要改文字的条目**。`retitle()` 只负责重写文字，既然这一对不用改，它们的句柄当初就没被存下来，也就没有任何一行去碰对勾。
  - **每个语言项的对勾是各自独立的**，Windows 不会因为你勾上了兄弟项就自动清掉旧的。所以刷新必须双向：对新语言 `set_checked(true)` **并且**对旧语言 `set_checked(false)`。只做前一半，就是「两项同时带勾」。
  - **`set_language` 对「已经是当前语言」提前返回。** 这行本身没错——翻译确实不用重做。但 **Windows 在点击的那一刻就把该项的对勾切换掉了**，事件到达应用时勾已经没了；提前返回等于把错误状态原样留在了屏幕上。现在这个分支会先把对勾重新对齐再返回。
- **顺带修掉一个只在单模块跑时才现形的测试缺陷**：托盘那几个测试原先会 `i18n::current()` 去读全局状态，而 `cargo test` 是**并行**跑测试的，另一个测试正在 `En` / `Zh` 之间来回设置它——整套跑时线程交错恰好蒙对，单独跑 `ui::tray` 就会红。现在语言由测试显式指定，改全局的地方用带锁的 `with_language()` 保护并还原，两个行为测试还改成**对两种语言各跑一遍**。
- 新增 5 个托盘测试。测试总数 64 → **69**。

### 0.1.4

- **修掉窗口最左侧与顶部那条 2–3 px 的横条**。逐像素量出来的是三个独立成因叠在一起，两个在 winit 里、一个在自己这圈描边上：
  - **客户区被下移了 1 px。** egui-winit 只要发现窗口没有装饰，就会顺手要求一个「无边框窗口投影」；winit 对这个标记的应答是把客户区矩形整体下移 1 像素（上游注释自己都写了「这会导致顶部出现 1px 黑边」）。用 `set_undecorated_shadow(false)` 把这个标记清掉即可。
  - **`WS_EX_WINDOWEDGE` 清不掉。** winit 在顶层窗口上留下了这个「凸起边框」的样式位（它只在 `CHILD` 分支里清），而应用自己清会被系统拒绝，且 winit 任何样式变化都会整个重写一遍。**这条路在 winit 这一档无解，已在开发笔记里记为否定结论**，省掉以后重复尝试。
  - **描边画到了两个像素上。** 原先 `shrink(0.5)` 再画 1 pt 内侧线，覆盖区间成了 `[0.5, 1.5]`：最外一个像素完全没被描到，相邻两个像素各被盖一半。改成**先把窗口边缘吸附到整数像素、再后退半个线宽**，于是每边恰好一个像素。
- **顺带修掉三条「凭空的分界线」**：标题栏 / 头部 / 页脚处的 `egui::Panel` 默认会各画一条通栏分隔线，而这三处的底色是**故意填成同一个白色**的——那条线在拆自己的台，已关闭。页脚另有一条理由：卡片本来就有边框。
- 这条修复补了 3 个单元测试（断言描边恰好盖住最外一个像素、不越出窗口、以及缩放系数异常时不产生坏矩形）。测试总数 61 → **64**。
- 0.1.3 那一版的标题栏与窗口修复**也在本次一并首次推送**（0.1.3 此前只在本地构建，未打标签）。

### 0.1.3

- **标题栏改成自己画的**：窗口原先戴着系统标题栏——Windows 10 上是一条灰底、硬直边、三个方形按钮的系统栏，紧贴在一层 8pt 圆角卡片的面板上面，一个窗口两种设计语言。而它**没法调**：`DWMWA_CAPTION_COLOR` 要 Windows 11 build 22000 起，按钮画在非客户区（应用拿不到那份画笔），按钮形状由主题的视觉样式决定。所以窗口改用 `with_decorations(false)`，标题栏由新增的 `src/ui/window_chrome.rs` 画，用的是面板下面同一套令牌（32 pt 高、46 pt 宽按钮，`Palette::surface` 底、`control_hover` 悬停）。关闭按钮的悬停红是固定的 `#C42B1C`，**没有**用 `palette.danger`——后者是为「在白卡片上当文字」调的，暗色主题下偏亮，白字形压上去只有 2.8:1，这个红有 5.4:1。
- **无边框窗口要还的债**，逐个补回来：移动窗口（`StartDrag`，Win 那套「拖标题栏还原最大化窗口」跟着一起来）、双击标题栏最大化、最大化时按钮换成「还原」字形、**缩放边框**（无边框 winit 窗口根本没有：`WM_NCCALCSIZE` 把整窗当客户区，`DefProc` 对每个像素回 `HTCLIENT`，所以自绘了 8 个前层热区）、**最大化时撤掉圆角**（四角就是屏幕角，切圆角等于在桌面上啃四口）、以及撤掉装饰后补的 1 pt 描边（没有投影也没有边缘，否则就是一块说不清边界色块）。
- 标题栏也给窗口设了图标，任务栏、Alt-Tab 与标题栏不会对「这个程序长什么样」有分歧。
- 窗口最小高度 480 → 512：标题栏占的那 32 点得补上，否则顶到最小高度时卡片会被挤掉一行。

### 0.1.2

- **调音面板加圆角**：Windows 10 没有 DWM 圆角 API，所以面板自己裁窗口区域（新增 `src/ui/window_shape.rs`，`GetWindowRect` + `CreateRoundRectRgn` + `SetWindowRgn`）。裁的是**窗口矩形**而不是客户区——按客户区裁会留下一圈仍然方角的边框。托盘菜单按 Windows 惯例保持方形。
- **修掉预设下拉的「跳动」**：行高原先会随指针移动而变化。egui 对「既未选中也未悬停」的行会丢掉 `Frame`，而描边是 `Frame` 度量的一部分，于是那一行在 **29 pt 与 31 pt** 之间切换，**它以下的每一行都跟着位移 2 pt**。现在每行都强制走带 `Frame` 的路径，再把 `Frame` 做成不可见：填充透明、描边**保留宽度只去掉颜色**（宽度就是行高，动不得）。
- **下拉视口改成整数行**：原先用 egui 默认的 200 pt 上限，装不满 8 行，底部留一条被裁剩的残行；滚动之后残行停在边缘，是「跳动」观感的另一半来源。现在视口 = 8 × 实测行高（248 pt），并且内边距从常量读，而不是从弹层**外面**那个 `ui` 读——后者当年算出 5 而不是 8，视口比它自称的 8 行短了 48 pt。
- **频段选项只留 5 与 10**：引擎本身接受 1..31，但上游只为 5 / 10 发布了频点，选 15 / 20 / 31 时 `eq_curve` 拿不到频率就**故意不画**——点了一定得到空曲线。与其留一个点了就空白的选项，不如去掉。
- **debug 构建不再弹黑色控制台窗口**：`windows_subsystem = "windows"` 原先只在 release 生效，于是控制台成了「只在 debug 存在的缺陷」，而 debug 恰恰是唯一会去看它的场合。日志本来就写文件（`init_logging`），不依赖控制台。

### 0.1.1

- 托盘菜单去掉中英并排的双语标签，改为单语言显示，菜单明显变窄。
- **界面整修**：调音面板从 egui 默认外观换成一套完整的设计令牌（`src/ui/theme.rs`），两套调色板都带对比度单元测试，并**跟随系统浅色 / 深色**。
- **均衡器改成图形化曲线**：31 行滑块换成一条可拖拽的频率响应曲线，双击归零、方向键微调，插值用单调三次样条——画出来的增益不会超过你设的值。
- **面板版式重排**：控制卡片由一列改为两列，窗口打开时按内容自适应高度，整块界面不再需要滚动；改成两列之前它想要将近 1000 点的高度，等于占满一整屏。
- **托盘菜单重新分组**（打开 / 状态 / 设置 / 维护），路由项在已生效时改为显示状态而不是置灰，`重新扫描预设` 移进它刷新的那个子菜单，**左键单击或双击托盘图标即可打开面板**。
- 底部运行时读数不再直接打印帧计数（欠载值几分钟就到八位数），改为按语言习惯缩写，精确值放进悬停提示。
- 切换语言不再重建托盘：`muda` 一直有 `set_text`，就地改写即可，避免重建失败时丢掉唯一的界面。
